Add an opt-in reference check. `harness-score --references` (or `score(root, { references: true })`) verifies that the files, directories, glob patterns and Markdown anchors cited in `AGENTS.md`/`CLAUDE.md`/`GEMINI.md`, scoped rules, skills and OpenSpec documents exist in the repository, and reports each occurrence with its position and one of five states: consistent, inconsistent, not evaluable, not supported or ambiguous. A missing target is inconsistent only when a Markdown link or a rule scope field names it; a missing path written in inline code or a code block is ambiguous, because code does not show that the path is meant as a target. A missing anchor is not supported when an `<a name>` or `<a id>` tag declares it, and inconsistent otherwise. The result is informational: it appears as a separate terminal and Markdown section and as the optional `references` field of the JSON report, and it never changes the score, the level, the checks or the exit code. Without the flag the output is unchanged. The same section also recognizes an OpenSpec structure and reports three independent properties: whether the structure exists, whether each active document has minimum content, and the states of the references those documents contain; archived changes are counted but not assessed. Every outcome carries a documented rule id (exported as `RULES`), and `packages/cli/REFERENCE-CHECK.md` specifies the exact behavior.

`ScanContext` gains two optional read-only methods: `hasDirectory(relPath)` reports whether any scanned file lives under a directory (empty directories are not detected), and `matchingGlob(pattern)` returns the scanned files matching a glob (literal segments, `*`, `?` and `**`), or `null` for unsupported syntax such as negation, braces or character classes. Both are optional, so existing implementations of `ScanContext` keep compiling.
